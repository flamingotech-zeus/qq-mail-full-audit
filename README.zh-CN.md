# QQ 邮箱全维度未读核查

[English](README.md) | [简体中文](README.zh-CN.md)

> MCP / IMAP / POP3 三通道交叉验证，突破 QQ 邮箱连接器的 30 天与 4 文件夹限制，把未读邮件真正翻到底。

## 这是什么

这不是一个"数一数你有多少未读"的脚本。数数是简单的那部分，也恰恰是大多数工具悄悄骗你的地方。

它要解决的是一个对不上的问题：第三方连接器只能看到最近 30 天、最多 4 个文件夹；手机上却显示"未读 380+"。这两个数字描述的是不同的集合，差额不是 bug，是协议和接口的限制。这个技能的做法是先把这道差额摆明白，再下结论。

## 为什么开源

公司里凡是需要把邮件盘清楚的时候都用它 —— 出差前、要确认待办清单可不可信的时候、以及几乎确定漏掉了某封重要邮件的时候。

值得放出来的理由：这一类工具几乎都只走到单个连接器的极限，然后把那个数字当成全部报给你。我们想设计掉的就是这个失败方式。它不含我们任何业务数据，分享前没有什么要剥离的。

## 能做什么

- **三通道交叉验证。** MCP 连接器、IMAP、POP3 分别查，结果是拿来比对的，不是合并成一个乐观的数字。
- **文件夹全覆盖。** 五个文件夹、已读未读都翻，而不是连接器卡死的四文件夹上限。
- **modified-UTF-7 解码。** IMAP 对非 ASCII 文件夹名用的是 modified UTF-7。不先解码，中文名的文件夹根本解析不出来。
- **只读拉取。** 取邮件时不标记已读，你的未读状态原封不动。
- **边界写清楚。** 每条通道真实能到哪一步，到不了什么，为什么到不了，都记下来了。
- **八条踩坑清单。** 做这个的过程中攒下来的，每条都写了症状和解法。

## 环境要求

Python 3 · QQ 邮箱 IMAP 授权码（不是登录密码）

## 安装

```bash
git clone https://github.com/<你的用户名>/qq-mail-full-audit.git
```

然后把整个目录放进技能目录：

| 系统 | 路径 |
|---|---|
| Windows | `C:\Users\<你>\.workbuddy\skills\qq-mail-full-audit\` |
| macOS / Linux | `~/.workbuddy/skills/qq-mail-full-audit/` |

没有构建步骤，重启对话即生效。

## 怎么用

直接提你的真实问题：

- "检查邮箱未读，到底有多少"
- "把邮箱所有未读都看一遍，列出需要处理的"
- "感觉漏了重要邮件，把邮箱翻一遍"

它会先确认交付边界，再把三条通道都查一遍，然后分两部分报：查到了什么，哪些够不着。

## 注意与边界

1. **这道差额是真的，写更好的代码也填不平。** POP3 是偏下载的协议，有自己的状态模型；IMAP 是服务端的文件夹语义；MCP 连接器有自己的时间窗口。把其中一个数字当成事实来报，才是错的那一步。
2. **用授权码，不是密码。** QQ 邮箱要单独开一个 IMAP 授权码。拿登录密码去连会失败，这是它应有的行为。
3. **设计上就是只读。** 这个工具没有"标记为已读"的选项，是故意的。
4. **会限流。** 对一个大邮箱高频查询，服务方会限你。
